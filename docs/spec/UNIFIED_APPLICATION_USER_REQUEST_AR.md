يجوز إتمام الدمج إلى `main` فقط بعد نجاح بوابات القبول المناسبة للإصدار المستهدف، واجتياز مراجعة الأمان والتكامل، وعدم وجود تغييرات غير متحققة أو تعارضات معلقة.

إذا فشل شرط أساسي:

**ممنوع دمج مشروع غير صالح في `main` لمجرد إنجاز الطلب شكليًا.**

احتفظ بفرع التكامل وPR مفتوح، وأصلح الإخفاقات، ثم أعد الاختبارات.

لا تكرر Commits الفروع المتراكبة، ولا تنسخ الملفات عشوائيًا، ولا تستخدم Force Push.

احتفظ بتاريخ واضح ومفهوم، وأغلق PRs القديمة بعد الدمج فقط عندما يثبت أن محتواها أُدرج بالكامل ولم تعد لازمة.

# 15. العمل المستمر والإنجاز الفعلي

لا تبدأ بتقرير نظري طويل ثم تتوقف.

اتبع دورة التنفيذ:

**Inspect → Implement → Test → Fix → Commit → Push → CI → Review**

كرر هذه الدورة لكل مرحلة حتى تستكمل جميع الأعمال الممكنة ضمن الصلاحيات والموارد الحالية.

عند اكتشاف فشل:

1. شخص السبب من السجل.
2. أصلح السبب الجذري.
3. أضف اختبار Regression عند الحاجة.
4. أعد الفحص.
5. لا تتجاوز الخطأ بحذف الوظيفة أو تعطيل الاختبار.

إذا تطلب جزء ما نموذج AI أو مصادر Biology أو توقيعًا أو موافقة خارجية غير متوفرة، وثّق العائق بدقة وانتقل إلى الأعمال المستقلة الممكنة دون اختراع بدائل.

احفظ العمل المنجز والمختبر في Commits مرفوعة إلى GitHub أثناء التنفيذ.

# 16. معايير التسليم النهائي

لا تستخدم عبارة «التطبيق مكتمل» إلا بعد إثبات اكتمال النطاق المعتمد.

قدّم تقريرًا نهائيًا منظمًا يجيب بوضوح عن:

1. هل المشروع أصبح شجرة Flutter واحدة؟
2. هل تم اعتماد تصميم V2 على الشاشات المطلوبة؟
3. هل بوابة Auth الإنتاجية متصلة وآمنة؟
4. هل تعمل المحادثات والحفظ والسجل؟
5. هل إدارة الموارد متصلة بخدمات B-07/B-12؟
6. هل Quiz يعمل ضمن مواصفة P0؟
7. هل LLM وRAG جاهزان فعليًا أم محجوبان؟
8. هل تعمل مكتبة PDF وقارئها؟
9. هل اجتازت الاختبارات الكاملة وAndroid؟
10. هل تم دمج `main` أم ما سبب منع الدمج؟
11. أين رابط سورس المشروع الكامل؟
12. أين رابط APK الواحد القابل للتثبيت؟
13. ما الذي يحتاج اختبارًا أو توفير مورد أو موافقة من صاحب المشروع؟

ارفق:

- روابط Commits.
- روابط PRs.
- روابط CI.
- روابط APK/ZIP.
- ملخص نتائج الاختبارات.
- قائمة النواقص الحقيقية فقط.
