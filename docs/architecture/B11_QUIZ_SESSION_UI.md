# B-11 / TK-10: Quiz UI and in-memory session

Authority: approved P0 v1.0.1 §§6.9,12.1–12.5,TC09/10/11/15/30/31 and revised TeamB B11. Independent branch from B08; no B09/B07/B04 changes copied.

Build QuizPort DTOs, conservative deterministic scoring, a guarded RAM-only controller, Arabic RTL question/feedback/summary UI and authenticated composition. The generation port must provide NEW LLM-generated items approved by A/C QuestionValidator, with reviewed answer specs and same-revision sources; its default is unavailable. No scientific fixture is installed in lib. No bank-only fallback, automatic generation-policy changes or fake product readiness. MAX_GENERATION_ATTEMPTS=2 belongs to the actual generation service; this UI never retries generation automatically.

MCQ and Boolean use reviewed keys; numeric tolerance is exact decimal arithmetic with reviewed, case-sensitive unit aliases (no inferred unit conversion); unmatched short answers are UNDETERMINED unless a reviewed alternative matches. No LLM judge. Invalid keys discovered after presentation are UNDETERMINED, while malformed output is rejected before UI. Ambiguous numeric input is an input error, not a scientific incorrect answer. Engineering input bounds:256 characters and exponent magnitude128; these are resource limits, not scientific quality thresholds.

Numeric answer specs also require immutable reviewed `NumericPrecision` metadata. A deterministic injected `NumericPrecisionPort` must validate the entire policy/configuration and evaluate the submitted representation. No rounding/significant-figure policy is selected implicitly: the default adapter is unavailable, unsupported metadata is rejected before display, and evaluation uncertainty/failure is UNDETERMINED. Actual A/C precision policy remains an explicit integration input; synthetic permissive adapters exist only in tests.

All questions/answers/feedback/counts exist only in RAM. Show summary within the open session, then end/close clears it; no QuizAttempt, history or settings persistence. UNDETERMINED is separate from correct/incorrect and excluded from judgeable. Logout/delete/nonce invalidation clears private content and cancels outstanding work. Late sessions cannot reappear after cancel/end/restart/dispose. The generator retains its native/revision resources until its own work drains; controller cleanup waits for outstanding port work when closed.

`QuizCleanupOwner` lives in app composition beyond any individual QuizPage. Failed cancel/discard closures retain only port and identifiers; retry runs on app resume, next quiz initialization, or explicit cleanup action, with coalesced bounded attempts. Disposed controllers can also explicitly retry cleanup; no failed resource ownership silently disappears with navigation. New generation is blocked while cleanup is pending/failed. Source reads and open dialogs are bound to the originating question and QUESTION phase, in addition to account/revision/session guards.

The controller uses a narrow access port implemented via existing SessionGuard and existing repository session watch, not widget SQL. Views render data and forward actions. A/C real generation, reviewed curriculum keys, Android offline/scientific acceptance and product resources remain pending independently of this Flutter UI implementation.
