# B-12 / TK-19 immutable dataset release core

Based on approved P0 v1.0.1 §§6.5,7.4.1,10.3,15.3 and TC12/26/32. Depends only on B07 PR3@27ff8e5. Logical PathResolver mapping within injected app support: rag/staging/<candidate_id> and rag/releases/<revision>. LLM/books/downloads-staging are never touched. Revision/candidate directory segments use a bounded path-safe grammar; no production catalog or manifest format is invented.

ApprovedDatasetPlans supplies immutable declarations plus exact extracted artifact paths/sizes/SHA256. Manager reuses RagCandidateContract: exactly five approved subject packs plus one shared embedding component, no PDF/LLM/fixture substitution. It never trusts downloaded metadata as expectations. A trusted assembler feeds file streams through writeArtifact after B07 transport; no archive parser/production URLs are chosen here. Space checks reuse B07 DownloadSpaceProbe; unknown capacity fails closed; IO/cancel leaves no completed artifact.

Only one manager owns the app-private rag root in the coordinator isolate; a writer file lock also excludes other processes. This is not an adversarial multi-isolate filesystem sandbox: all cooperating app writers must use this owner, and no external writer may modify this private tree. Candidate writes, validation, promotion and cleanup are mutually exclusive. Trusted runtime validation adapters receive read-only-by-contract directories and must drain all temporary native work. They perform actual schema/chunk/index/embedding/config/Android-query validation, not return check-name inventories; the default throws validatorUnavailable. No approval is inferred from byte hashes alone.

After exact-tree/real SHA256 validation and actual trusted runtime validator success, the manager creates an unforgeable manager-owned receipt. Candidate is sealed; commit re-resolves approved expectations and rehashes bytes, rejects any existing release directory, renames without a copy fallback, verifies promoted bytes, then transactionally compare-and-swaps the one reserved installed_resource row RAG_PACK/__ACTIVE_DATASET__ (READY, revision, path). Unverified generic registry writes cannot target this row. Cancellation is checked before durable commit, never reported as failure after a successful commit. A failure after rename leaves an unreferenced directory; it is never automatically activated or deleted by the failure path.

RevisionPinnedHandle owns one exact plan/revision/directory through caller-native-work drainage. Old readers survive a switch; old release deletion and manager close are blocked while pinned. A validator unable to coexist with pinned readers cannot validate a replacement until those readers drain. Runtime proof is reused for the same exact approved plan during a manager lifetime; all bytes are checked on handle open, and recover forces runtime revalidation. Any failed revalidation revokes the cached runtime proof; no new handle can bypass the failed check. Cleanup is explicit, bounded to this owned namespace, link-rejecting and blocked for current/pinned releases. Recovery validates the current pointer and scans releases/staging; it reports unreferenced revisions and abandoned candidates without inferring readiness from directory existence. Previous-active directories and never-committed orphans are both unreferenced: existence alone does not prove activation history.

Data/SQLite boundary is DatasetPointerStore, an internal persistence primitive called by the manager, not a resource readiness API. No schema version/table/dependency/Auth/user-data changes. No fixture API writes or product-ResourceStatus integration is installed. Default catalog/validator cannot activate anything. True five-pack consent/download/aggregate-progress UI, trusted archive extraction, actual C manifest/catalog serialization, production validators and native/runtime resource adapters remain explicit integration inputs. B09/G2/G3 priority remains independent; this mechanism's synthetic port tests are not product scientific/Android proof.

Durability limit: file streams are flushed and SQLite transactions are real; rename and commit fault boundaries are tested on Linux with restart/revalidation. No OS power-cut/device/parent-directory fsync proof is claimed. Android crash/power-loss and device storage/runtime validation remain pending; no G2/G3 or Product Ready is claimed.

Observable cancellation wakes a stalled assembly stream consumer, cancels/drains its subscription, and retains exclusive writer ownership until cleanup finishes. Runtime-validator cancellation remains cooperative: it must drain before returning, and no receipt/promotion occurs after cancellation. File-backed SQLite restart tests reopen the physical database after a failed promoted update; this is still not a physical power-cut test.
